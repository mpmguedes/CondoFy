## O que está feito

- `agruparPorPermilagem(fracoes)` — grupos por igualdade **exata** da permilagem

  `id` (tie-break D3).
- `distribuirPorGrupos(totalC, grupos)` — maior-resto ao nível do **grupo**;

  `{ porFracao, totalTeoricoC, grupos, diferencaArredondamento: { totalC: R1, fcrC: R2, estruturalC: E1 } }`.
- `fcrTeoricoC`, `permilagemEscalada`, `permilagemDeEscala`, `normalizarPercentagem`.

**Aritmética exclusivamente em cêntimos inteiros** (I-01); nenhuma dependência de
BD, sessão ou pedido.

## 🔴 O bloqueio — I-08 falha 20 977 vezes em 40 000

**I-08 pede:** `|residualC| ≤ nGrupos`.

**A medição:**

```
casos = 40 000
falhas I-08 = 20 977   (52 %)
residual máximo observado = 26    (com nGrupos entre 1 e 8)
```

### Causa — é estrutural, não é bug de implementação

O residual tem **duas origens** com naturezas diferentes:

| Origem | Grandeza | Ligado a |
|---|---|---|
| Maior-resto **entre grupos** | ≤ `nGrupos` cêntimos | D3 (respeita I-08) |
| Resto **dentro do grupo** (`valorGrupo mod nMembros`) | até `nMembros − 1` cêntimos **por grupo** | D3 (igualdade) |

A segunda origem é **imposta por D3**: se os membros têm de receber exatamente o
mesmo, o quinhão indivisível **não pode ir para um deles**. Tem de sobrar. E com
`n` membros sobram até `n−1` cêntimos.

**Escala máxima do resto intra-grupo (medido, 1 grupo só):**

| Membros no grupo | Residual máximo | I-08 exigiria |
|---|---|---|
| 3 | 2 | ≤ 1 |
| 5 | 4 | ≤ 1 |
| 7 | 6 | ≤ 1 |
| 8 | 7 | ≤ 1 |
| 20 | 19 | ≤ 1 |
| 50 | 49 | ≤ 1 |

### A contradição, em uma frase

**D3 (igualdade exata por grupo, sem tolerância) e I-08 (`|residualC| ≤ nGrupos`)
não podem valer ao mesmo tempo.** São duas decisões fechadas que se excluem.

Se o grupo é **grande** (ex.: 50 frações de `20,00‰`), o resto pode chegar a
**49 cêntimos** num só grupo — 49× o limite que I-08 declara.

### O caso concreto que expõe a contradição

```
50 frações de 20,00‰  ·  total teórico = 50,00 €  (= 5000 c)
valor exato por fração = 5000 / 50 = 100,00 c   → divide certo, residual 0

Mas com total = 5001 c:
  valor por fração = floor(5001/50) = 100 c
  Σ = 5000 c
  residualC = 1    ✅ dentro de I-08 por sorte

Com total = 5049 c:
  floor(5049/50) = 100 c
  Σ = 5000 c
  residualC = 49   ❌ I-08 exigiria ≤ 1
```

## As três saídas — não escolho por iniciativa própria

### Opção A — corrigir I-08 para refletir D3 (a que a matemática impõe)

```
|residualC| ≤ nGrupos + Σ (nMembros(g) − 1)
```

O limite passa a depender do **número de frações em grupos com mais de um membro**,
não do número de grupos. É o limite verdadeiro da distribuição sob D3.

- **Prós:** não muda nenhum valor; é o único limite matematicamente consistente
  com D3; continua a ser um limite apertado e demonstrável.
- **Contras:** I-08 deixa de ter a forma simples pedida. O limite passa a ser
  ≤ (nº de frações − nº de grupos com 1 membro), ou seja, quase `nFracoes` outra
  vez — perde-se a mensagem «o residual é minúsculo».
- **Nota:** na prática o residual observado é 0 na esmagadora maioria dos casos
  (só aparece quando o total não divide). O pior caso só surge em totais adversos.

### Opção B — manter I-08 e relaxar D3 só para o cêntimo indivisível

Quando `valorGrupo` não é divisível por `nMembros`, distribuir o resto por
membros **segundo `ORDER BY id`** (D3 já fixa este tie-break para empates).

- **Prós:** I-08 mantém-se exatamente como pedido (`≤ nGrupos`); o residual
  desaparece da intra-grupo.
- **Contras:** **viola D3** — «todas as frações do mesmo grupo recebem o mesmo
  valor» deixa de valer em 1 cêntimo. O exemplo da especificação (§C: 3 frações
  de `333,33‰`) voltaria a dar `333,34 / 333,33 / 333,33`.
- **É exatamente o comportamento que a Fase A existe para eliminar.**

### Opção C — manter as duas e declarar I-08 como «limite típico, não garantia»

Nenhuma alteração de código; I-08 passa de invariante a observação estatística.

- **Prós:** zero mudança.
- **Contras:** um invariante que não se verifica em 52 % dos casos aleatórios
  **não é um invariante**. Não pode ser asserção de teste. Chama-se «invariante» a
  algo que não é — é a definição de teste que se satisfaz sem observar.

## A minha leitura (não uma decisão)

**A está correta e B é a armadilha.** A razão:

A Fase A existe precisamente para **eliminar** a fração privilegiada. O
`distribuirPorPesos` antigo escolhia um dono para o cêntimo; a opção B reintroduz
esse comportamento, apenas mudando o critério de escolha (de «maior resto» para
`ORDER BY id`). O utilizador fechou D3 com a frase explícita: *«Não atribuir o
cêntimo residual arbitrariamente a uma fração na Fase A.»* — a opção B faz
precisamente isso.

O que **falta** é reconhecer que D3 tem um **custo**: ao proibir a fração
privilegiada, o residual cresce até `nMembros − 1` por grupo. I-08 foi escrito
antes de essa consequência ser visível. Não é I-08 que está «errado» — é que
I-08 e D3 foram redigidos sem se confrontarem.

Se a decisão for **A**, o texto de I-08 fica:

```
I-08  residualC = totalC − Σ partes
      |residualC| ≤ nGrupos + Σ_g (nMembros(g) − 1)
      (limite: nº de frações em grupos com mais de um membro)
      0 ≤ residualC   (o maior-resto nunca produz parte negativa)
```

e o T3 testa este limite, com o caso de 50 frações incluído.
